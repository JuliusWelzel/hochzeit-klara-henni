# Stadionticket Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sektion „03 Tickets“ mit Formular, die ein Stadionticket als Bild (PNG) und eine .ics-Datei erzeugt – alles im Browser.

**Architecture:** Reine Logik (Texte, Platz, ICS) in `ticket-core.js` als ES-Modul, mit `node --test` getestet. `ticket.js` (ES-Modul) verdrahtet das Formular und zeichnet das Ticket auf ein `<canvas>`; dieses Canvas ist zugleich Anzeige und PNG-Quelle. Keine externen Scripts, keine Speicherung.

**Tech Stack:** HTML, CSS, Vanilla JS (ES-Module), Canvas 2D, Node ≥ 18 nur für Tests.

**Spec:** `docs/superpowers/specs/2026-11-24-ticket-design.md`

## Global Constraints

- Kein Netzwerk-Request mit Gästedaten, kein Token, keine externen Scripts.
- Farben/Schriften aus `style.css`: `--red #810100`, `--maroon #630000`, `--white #edebdd`, `--ink #1b1717`, Anton / Oswald / Source Serif 4.
- Datum 05.11.2027 (Freitag), Ort „Bauer Kammesheidt, Kamisheide 50, 45133 Essen“; Uhrzeit offen → ICS ganztägig.
- Personen 1–6; Essen pro Person: Fleisch / Vegetarisch / Vegan; Allergien optional.
- Texte deutsch.

## Review Focus

- Leerer bzw. nur aus Leerzeichen bestehender Name → Formular verweigert, kein Ticket.
- Sehr langer Name (40+ Zeichen) → wird auf dem Ticket verkleinert/gekürzt, läuft nicht über den Abriss.
- Umlaute/Sonderzeichen im Namen → korrekt auf Ticket und im Dateinamen (`ticket-klara-mueller.png`).
- Personenzahl ändern nach Essensauswahl → Essensfelder passen sich an, bisherige Auswahl bleibt erhalten.
- iPhone Safari: „Ticket speichern“ nutzt `navigator.share` mit Datei, sonst Download-Link.

### Task 1: Logik-Modul `ticket-core.js`

**Files:**
- Create: `ticket-core.js`
- Test: `tests/ticket-core.test.mjs`

**Interfaces:**
- Produces:
  - `summarizeMeals(meals: string[]) -> string` – z. B. `["Fleisch","Vegan","Fleisch"]` → `"2× Fleisch, 1× Vegan"` (Reihenfolge Fleisch, Vegetarisch, Vegan).
  - `seatFor(name: string) -> {block: string, row: string, seat: string}` – deterministisch aus dem Namen; `block` immer `"K&H"`, `row` zweistellig 01–30, `seat` zweistellig 01–40.
  - `slugify(name: string) -> string` – `"Klara Müller"` → `"klara-mueller"`; leer → `"gast"`.
  - `buildIcs() -> string` – VCALENDAR mit einem ganztägigen VEVENT `DTSTART;VALUE=DATE:20271105`, `DTEND;VALUE=DATE:20271106`, `SUMMARY:Hochzeit Klara & Henni`, `LOCATION:` mit Komma-Escaping, CRLF-Zeilenenden.

- [ ] **Step 1: Tests schreiben** – `summarizeMeals` (Beispiel oben, leeres Array → `""`), `seatFor` (gleicher Name → gleiches Ergebnis, Formatprüfung per Regex `/^\d{2}$/`), `slugify` (Umlaute ä→ae, ö→oe, ü→ue, ß→ss; `"  "` → `"gast"`), `buildIcs` (enthält `DTSTART;VALUE=DATE:20271105`, `Kamisheide 50\\, 45133 Essen`, jede Zeile endet auf `\r\n`).
- [ ] **Step 2:** `node --test tests/` → FAIL (Modul fehlt).
- [ ] **Step 3:** Funktionen implementieren (seatFor: einfacher String-Hash, modulo).
- [ ] **Step 4:** `node --test tests/` → alle PASS.
- [ ] **Step 5:** Commit.
